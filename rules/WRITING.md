# Plain Language

Apply ISO 24495-1:2023 to project-authored text: rules, guides, README files,
comments, docstrings, node help, tooltips, labels, errors, and workflow notes.

- Include the information readers need for their task. Omit irrelevant detail.
- Put the main point first. Use descriptive headings and a clear reading order.
- Use familiar words, short sentences, and active verbs. Explain technical terms
  when readers need them.
- Give concrete instructions. State who acts, what they do, and when a condition
  changes the action.
- Use one name for each concept. Keep exact API identifiers, product names, and
  required legal text unchanged.
- Describe current behavior. Keep implementation history, private reasoning,
  acceptance status, and temporary development notes out of public content.

Read the changed text for clarity, accuracy, and usefulness. Review only the
material affected by the task. Do not require a separate reviewer or approval.
Run formatting, spelling, rendering, or other verification commands only when
explicitly requested. Passing those checks does not establish ISO conformity.
