# Plain Language

All project-authored text must strictly conform to ISO 24495-1:2023.
Apply this requirement to README files, guides, Markdown, comments, docstrings,
node help, tooltips, labels, errors, workflow notes, examples, and generated text.

Write for the reader's task. Include the information they need, put it where
they can find it, explain it in familiar words, and make the next action clear.
Use short, direct sentences and explain technical terms when readers need them.
Use the same name for the same thing. Follow the documentation rule for casing
and formatting. Preserve exact API identifiers and legal license text.

Describe current behavior. Do not include implementation history, private
reasoning, acceptance status, or temporary development notes in public content.

Review source text and every rendered surface it produces. Check that readers
can find, understand, and use the information. Formatting and spelling checks
support this review; they do not establish ISO conformity on their own.
