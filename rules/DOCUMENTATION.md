# Documentation rules

Write for the reader's task. Keep README focused on installation, credentials,
the first workflow, supported scope, and links. Put details in focused guides.
Describe available behavior and user-relevant limits. Keep test results,
implementation journals, temporary status notices, and run history outside
the public repository. Never put them in workflows, node help, or UI copy.

Node definitions own socket facts. Authored node guides own instructions and
examples. Generate native help from these sources and check for drift.
Every example must load in its stated environment and contain no secret or
machine-specific path.

Update help with behavior changes. Validate links, rendered help, examples,
and actual UI text. Keep source-backed claims dated where contracts can change.
Apply [strict ISO 24495 conformance](PLAIN_LANGUAGE.md) to all project text.
